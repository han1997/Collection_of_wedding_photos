# 婚礼照片收集助手

每场婚礼一个二维码，宾客扫码上传当天的照片和视频，**所有原文件直接落到你自己的 NAS 上**。

主持人（你）能看到、下载所有场次、所有宾客上传的全部素材；
宾客上传后只能看到自己传的内容，彼此之间互不可见。

> **当前状态：功能已完整，可用。**
> 后端（登录、分片上传、断点续传、媒体处理、二维码、管理接口）与小程序
> （宾客上传/浏览、主持人建活动出码）都已实现，107 项自动化测试全部通过。
> 尚未在真实婚礼上跑过，也尚未提交微信审核。

---

## 它解决什么问题

婚礼现场宾客拍了一堆照片，散在几十个人的手机里，事后一张都要不到。
这套系统给现场放一个二维码：

1. 宾客扫码 → 进入这场婚礼
2. 挑照片和视频 → 上传（支持断点续传，弱网也不怕）
3. 上传的内容**原图原样**存进你的 NAS，在飞牛的文件管理器里直接就能翻
4. 你在小程序里管理每一场婚礼，导出、删除、收官

**不需要注册微信小程序之外的任何服务，没有第三方云存储，照片不出你的家门。**

## 关键设计取舍

| 决策 | 为什么 |
| --- | --- |
| 宾客只能看自己传的 | 规避 UGC 公开社区的合规风险，也天然免去审核队列 |
| 原图逐字节原样保存 | 缩略图失败也不影响数据完整性；HEIC 也能原样留存 |
| 分片 + 断点续传上传 | `wx.uploadFile` 有 60 秒超时且无法续传；相册里的长视频可达数 GB |
| 默认**不转码**视频 | 弱 NAS 上转 4K 会钉死 CPU，而那时其他宾客还在上传 |
| `node:sqlite` 而非 better-sqlite3 | 去掉原生编译依赖（Docker 构建里最易炸的一环），封装成一层便于回退 |
| tmp 与 events 同盘 | 合并靠 `fs.rename`，同盘才原子；跨盘会退化成整文件拷贝 |
| 管理后台放在小程序里 | 婚礼当天你在手机上，再写一套 Web 前端是双倍工作 |

## 本地开发

前置：Node ≥ 22.5（本项目用 Node 内置的 `node:sqlite`），微信开发者工具。

```bash
# 1. 装依赖
npm install

# 2. 准备配置（首次）
cp .env.example .env
# 生成随机密钥，填进 .env 的 JWT_SECRET / FILE_TOKEN_SECRET
openssl rand -base64 48

# 3. 起服务（会自动建目录、建表）
npm run dev
# → http://127.0.0.1:3000/api/health

# 4. 建管理员账号（也可由服务首启自动完成）
npm run seed-admin
```

跑测试：

```bash
npm test
```

本地开发时数据落在 `_data/`（已被 gitignore）。

### 小程序端

用微信开发者工具打开 `miniprogram/` 目录。本地联调时：

- 在「详情 → 本地设置」勾选 **不校验合法域名、web-view、TLS 版本以及 HTTPS 证书**
- 把 `miniprogram/utils/config.js` 里的 `BASE_URL` 指向本机局域网 IP（不是 `127.0.0.1`，手机连不到）
- 真机调试同样能绕过域名校验，所以**没有备案域名也能先跑通全流程**

## 部署到 NAS

见 [docs/deploy-fnos.md](docs/deploy-fnos.md)。核心就三步：

```bash
# 在 NAS 上（SSH）
mkdir -p /vol1/1000/docker/wedding-collect
sudo chown -R 1000:1000 /vol1/1000/docker/wedding-collect
docker compose up -d --build
```

⚠️ 最常见的首跑失败就是**目录属主不是 uid 1000**，症状是第一次上传报 `EACCES`。

```bash

```

107 项测试，覆盖：

- **越权**：宾客 B 看不到、猜不到、删不掉宾客 A 的素材；跨活动隔离；令牌类型不可混用

## 注意事项

- **不要手工改名或移动 NAS 上的照片文件。** 数据库才是索引，文件路径是指针。
- **AppSecret 只存在于服务端 `.env`**，绝不写进小程序代码或 `project.config.json`。
- `_data/`（或你的 `DATA_ROOT`）里既有原图也有数据库，**把它一起备份就是完整备份**。
- 数据目录必须是**普通目录（bind mount）**，且指向 NAS 本地磁盘，
  不能是 NFS/SMB 挂载点（SQLite 的 WAL 不支持网络文件系统）。

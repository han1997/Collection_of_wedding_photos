# 现场使用手册

给主持人自己看的。婚礼当天照着做就行。

---

## 婚礼前（提前一天）

### 1. 建活动

小程序 → 首页 → **主持人入口** → 登录 → **＋ 新建婚礼活动**

填写：

- **活动名称**（必填）：`张伟 & 李娜 婚礼`
- **新人姓名**：会显示在宾客看到的页面上
- **婚礼日期**、**场地**
- **欢迎语**：宾客进来第一眼看到的话。写一句有温度的，比空着强

点「创建并生成二维码」，会自动跳到详情页。

### 2. 生成并保存二维码

在活动详情页：

1. **确认「生成版本」选对了**（见下表），不对就换
2. 点 **重新生成**
3. 点 **保存到相册**

| 版本 | 什么时候用 |
| --- | --- |
| **正式版** release | **小程序已经发布了 → 正式办婚礼就用这个** |
| 体验版 trial | 小程序还没发布，只有体验成员能扫开。自己测试用 |

> ⚠️ **这一条最容易出错，而且代价很大**：版本选错，印出来的码宾客扫了是白屏。
> 婚礼前一天**必须用另一台手机实扫一遍**确认能打开。

### 3. 打印

二维码在相册里了。建议**做成海报**贴在：

- 签到台 / 迎宾区
- 每张餐桌的立牌上
- 舞台背景板

**把活动码一起印上去**（8 位，形如 `A1B2C3D4E5`）。
万一有宾客扫不开（网络、微信版本、码印糊了），还能手动输入进入。
活动码在详情页点一下就能复制。

### 4. 自己先测一遍

用你自己的微信进一次活动，传一张照片，确认：

- [ ] 扫码能打开
- [ ] 能选中照片并上传成功
- [ ] 传完能在「我上传的」里看到
- [ ] 回到活动详情页，统计数字涨了

**测试完记得把手动传的那几张删掉。**

## 婚礼当天

### 开场前

- 二维码海报/台卡摆好
- 详情页看一眼，上传通道是**开启**状态

### 现场引导（这几句话很有用）

- 司仪口播：「欢迎大家扫码上传今天拍的照片，只有你自己能看到，我们会在婚礼后整理好」
- 或者直接说：「桌上有个码，扫一下把照片传给我们」

### 如果宾客说传不上去

按顺序排查：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 扫出来白屏 | 二维码版本不对 | 罕见于已发布的正式版；检查是不是印了旧的体验版码 |
| 提示「活动不存在或已结束」 | 扫的是别的场次的码 | 确认二维码是这一场的 |
| 一直失败、进度不动 | 现场网络差 | 让宾客**把上传页保持在前台**，别切出去；等信号好了会自动接着传 |
| 传了一半没传完 | 切到聊天/锁屏了 | 回到上传页会**自动续传**，不用重传 |
| 提示「文件类型不支持」 | 非图片/视频文件 | 只能传常见的图片和视频格式 |
| 提示「本场活动已关闭上传」 | 上传通道被关了 | 到详情页点「开启上传」 |

### ⚠️ 三件事别做

1. **别在活动期间看 NAS 上的视频**——会和宾客上传抢同一条上行带宽
2. **别暂停上传通道**，除非确实要收工了
3. **别删活动**——删除会归档整场活动，照片虽然还在但列表里就看不到了

## 婚礼后

### 收工

活动详情页 → **结束这场活动**。

结束后宾客不能再传，**已上传的照片一张都不会丢**，随时可以再打开。

### 取照片

这是本项目最省事的地方：**你根本不需要下载。**

照片就在 NAS 上，用 fnOS 的文件管理器打开（或走 SMB 挂载到电脑）：

```
/vol1/1000/docker/wedding-collect/
└─ events/
   └─ 2026-10-05_张伟-李娜_1EUmNlKFjU/
      ├─ .event.json          ← 这场婚礼的信息
      ├─ qr.png               ← 二维码留档
      └─ 2026-10-05/          ← 按上传日期分目录
         ├─ originals/        ← 原图（逐字节原样，直接拿去修图）
         ├─ previews/         ← 长边 1600 的预览图
         ├─ thumbs/           ← 小图
         └─ posters/          ← 视频封面
```

文件名长这样：

```
183045_000016_李阿姨_1779273045123_a1b2.jpg
└┬───┘ └┬───┘ └┬──┘ └────┬─────┘ └┬─┘
 上传时刻  谁传的  称呼   毫秒时间戳  防碰撞
```

**按文件名排序就是时间顺序**，正好是按时间线挑片。

### ⚠️ 不要手工改名或移动文件

数据库里存的是文件路径，改名或移走之后服务就找不到它了。
要整理的话，**先把整场活动的文件夹复制一份再整理副本**。

## 常见问题

**Q：宾客能看到别人传的吗？**
不能。每位宾客只能看到自己上传的。这是刻意的设计——
既是隐私保护，也是让这个小程序能作为「工具」而非「社区」过审的关键。

**Q：宾客传错了能删吗？**
能。宾客自己可以在「我上传的」里长按删除；你也可以在活动详情页删任何一张。

**Q：视频能传多长？**
从**相册里选**的视频不限时长（微信只限制在小程序内现场拍摄不超过 60 秒）。
但视频越大越容易受网络影响，建议引导宾客传精彩片段就好。

**Q：iPhone 拍的照片（HEIC）能传吗？**
能，而且**原图会逐字节原样保存**。
如果缩略图生成失败，网格里会显示占位图标，但照片本身完好，可以直接从 NAS 取用。

**Q：一场大概占多少空间？**
约 50 GB。一年 30 场就是 1.5 TB，提前看下盘够不够。

**Q：需要下载备份吗？**
不需要单独下载。**备份整个 `/vol1/1000/docker/wedding-collect` 目录**就是完整备份，
原图和数据库都在里面。用你现有的 NAS 备份任务覆盖它就行。

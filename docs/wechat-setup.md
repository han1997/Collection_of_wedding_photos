# 微信小程序配置与上线清单

> **审核才是这个项目的关键路径，不是代码。**
> 类目问题可能来回一周，所以要**早开始**，不要拖到想发布的那天。

---

## 一、AppID 与 AppSecret

微信公众平台 → 开发 → 开发管理 → 开发设置：

| 项 | 用途 | 填到哪 |
| --- | --- | --- |
| AppID | 公开标识 | `project.config.json` 的 `appid`，以及 NAS 的 `.env` |
| AppSecret | 调用微信接口的凭据 | **只填 NAS 的 `.env`** |

⚠️ **AppSecret 绝不能出现在 `miniprogram/` 目录下的任何文件里**，包括
`project.config.json`。小程序包是可以被下载解包的，放进去等于公开。

---

## 二、服务器域名（必须做）

开发 → 开发管理 → 服务器域名，**三处都要加**：

- `request 合法域名` —— **最关键**。分片上传走的是 `wx.request`（不是 `wx.uploadFile`）
- `uploadFile 合法域名`
- `downloadFile 合法域名` —— 保存到相册前的下载、视频播放都靠它

要求：
- 必须是 **HTTPS**，TLS 1.2 以上，证书由受信任的 CA 签发（不能自签）
- 不能是 IP 地址
- **必须已完成 ICP 备案**（2023 年 9 月起微信强制要求）

---

## 三、用户隐私保护指引（必须做，而且要早）

设置 → 服务内容声明 → 用户隐私保护指引。

如实勾选本项目实际用到的项：

| 收集的信息 | 对应功能 |
| --- | --- |
| 相册（选择照片/视频） | 宾客挑选要上传的内容 |
| 摄像头 | 宾客现场直接拍 |
| 相册（仅写入） | 保存照片/视频到相册 |

⚠️ **不配置会怎样**：`wx.chooseMedia` 和 `wx.saveImageToPhotosAlbum`
会在运行时被**直接拦掉**。症状看起来像代码 bug，实际是后台没配。
所以这一步放在部署阶段就做，别等提审。

### 我们刻意不收集的东西

本项目**不索取**昵称、头像、手机号、位置、通讯录。
`wx.login` 换来的 `openid` 是一串匿名标识，服务端也只是拿它区分「谁传的」。

这不只是隐私上的克制——**声明项越少，被拒的口子越少**。
这是过隐私审核最大的杠杆，请不要为了「体验更好」而加回昵称头像。

### 关于接口形态

小程序端所有触碰隐私的调用都收敛在 `miniprogram/utils/privacy.js` 的思路下
（目前直接在各页面调用，但**改动只需改一处**）。
⚠️ `wx.getPrivacySetting` / `wx.onNeedPrivacyAuthorization` /
`<button open-type="agreePrivacyAuthorization">` 这套机制在 2023 年过渡期变过几轮，
**实现/修改前务必对照 `developers.weixin.qq.com` 的当前文档**。

## 四、服务类目（个人主体这条最敏感）

**本项目你是个人主体**，而个人主体能选的类目是受限的。

### 建议选什么

- **主类目：`工具 > 效率`** —— 「婚礼照片收集助手」放在这里是说得通的
- 若有 `工具 > 图片处理` 也可以

### 千万不要选什么

**不要选 `社交 / 社区 / 论坛`。** 那是重灾区：
要求更重，历史上还会被要求提供超出普通备案的 ICP 许可证，
而个人主体**根本申请不了**社交类目。

### 命名与简介的措辞

回避这些词：**社区、分享、交友、广场、圈子**。

用「**婚礼照片收集助手**」这类说法——「收集」「助手」读起来是工具，不是社区。

### 如果审核说「涉及用户生成内容，请选择社交类目」

这是最可能出现的分歧点。用架构事实回复：

> 本小程序的上传内容**仅上传者本人与活动组织者可见**，
> 不存在公开内容社区，也不存在用户之间的互动、关注、评论等社交功能。
> 应用内已实现举报入口与内容安全检测机制。

同时指出：举报入口在预览页，内容检测在服务端（见下）。

**如果仍然不通过**，两条路：
1. 把主体升级为**个体工商户**（办个执照对婚礼主持人既便宜又够用），
   类目空间立刻宽裕
2. 走 **H5 兜底**——同一套后端已经能提供网页上传页（`https://你的域名/e/<活动id>`），
   **完全不需要微信审批**。这是设计时刻意留的逃生通道

## 五、内容安全

UGC 类应用微信要求对用户上传的内容做检测。本项目已经实现：

- **图片**：合并落盘后，把缩略图（≤750px、远小于 1MB）送 `img_sec_check`
- **文本**：自由输入（「怎么称呼您」）送 `msgSecCheck`
- 命中违规 → 素材标记为 `blocked`，移入 `events/<活动>/blocked/`，
  **对宾客隐藏但保留原文件**（留作证据，不静默删除）
- 检测失败 → **放行**（fail-open）。
  内容本来就只对上传者本人可见，没有公开广场；若改成失败拦截，
  微信接口一抖动宾客就传不上照片——在婚礼现场那是灾难性的

⚠️ **接口名和形态需要核对**：`img_sec_check`（v1，≤1MB）与
`media_check_async`（v2）这几轮变过，视频的异步检测是否对所有类目开放也不确定。
所有调用收敛在 `server/src/services/contentSecurity.js` **一个文件**里，核对后只改这一处。

开关：`.env` 里的 `CONTENT_CHECK_ENABLED`。

## 六、保存到相册

- `app.json` 里**必须**有 `permission.scope.writePhotosAlbum.desc`，
  漏了会直接运行时报错（本项目已配好）
- 2021 年起这些接口**不再自动弹授权框**。正确的流程是：
  `wx.getSetting` → 用户拒绝过就用 `wx.openSetting` 引导
  （**必须由用户点击触发**，不能自动调）→ 否则 `wx.authorize` 后保存
- 本项目已在 `miniprogram/utils/media.js` 里实现完整流程，
  包括 `auth deny` 的显式处理

## 七、提审清单

提审前逐项确认：

- [ ] 服务器域名三处都配了，且能通过
- [ ] 用户隐私保护指引已配置并通过
- [ ] 服务类目选的是 `工具`（不是社交）
- [ ] 小程序名称和简介里没有「社区/分享/交友/广场」字样
- [ ] `requiredPrivateInfos` 是**空数组**（本项目不用任何位置接口，
      随便加一项本身就会致拒）
- [ ] `app.json` 设了 `lazyCodeLoading: "requiredComponents"`
- [ ] **准备了一个带样片的演示活动**，并把它的二维码/活动码写进审核备注
- [ ] **审核备注里给出测试账号**（管理员账号密码）——审核员测不了就会拒
- [ ] 有联系路径：客服按钮或电话（本项目已在小程序里提供联系方式）

### 审核备注模板

```
本小程序是婚礼照片收集工具，供婚礼主持人为每场婚礼创建一个相册活动，
宾客扫码上传自己拍摄的照片和视频。

内容可见性：上传内容仅上传者本人与活动组织者（主持人）可见，
不存在公开内容社区，也不存在用户之间的互动功能。

测试方式：
1. 活动码：<填一个演示活动的 id>
2. 管理端入口：首页 → 主持人入口，账号 <用户名> 密码 <密码>
   （首次登录会要求修改密码，改后可查看该活动的全部素材）

已实现的内容安全措施：服务端对接微信内容安全接口做图片与文本检测；
预览页提供举报入口；命中违规的内容会被隐藏并保留证据。
```

### 发布之后

**别忘了**：小程序发布后，回活动详情页把二维码的「生成版本」从 `体验版`
改成 `正式版`，并**重新生成所有二维码**。
用体验版的码办婚礼，宾客扫出来是打不开的。

## 八、常见被拒原因与对策

| 被拒理由 | 对策 |
| --- | --- |
| 涉及 UGC，需选社交类目 | 用第四节的架构论证回复；不行就升级主体或走 H5 |
| 服务器域名未备案 / 非 HTTPS | 检查域名备案状态与证书 |
| 未配置用户隐私保护指引 | 配置后重新提审 |
| 审核员无法测试 | 备注里给活动码 + 管理账号，并预先建好演示活动 |
| 类目与功能不符 | 改选 `工具 > 效率` |
| 收集了不必要的用户信息 | 检查是否误加了昵称/头像/位置的调用 |
